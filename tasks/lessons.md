# Lessons

## 日本語コピー/組版
- **和文フォント未指定が「翻訳感」の最大要因**：欧文フォント（Inter等）のみだと日本語はOSフォールバック表示になり、字面・ウェイトが揃わず安っぽく見える。日本語ページには必ず Noto Sans JP 等の和文フォントをスタックに含め、見出しに `font-feature-settings: "palt"`、本文に広めの `line-height` を当てる。
- **JSONに `<br>` を埋め込まない**：特定画面幅前提の改行は他幅で崩れる。BudouX + `max-width` + `text-wrap: balance/pretty` で制御する。
- **読点前後の折り返し禁止（ワードジョイナー挿入）は逆効果**：日本語では読点直後はむしろ自然な改行位置。`line-break: strict` の禁則処理で十分。不可視文字はコピペやBudouX解析に混入する副作用もある。
- **表現の重複と比喩の渋滞を避ける**：「一気通貫」「伴走」等の強い語は多用すると翻訳ツール感が出る。サイト全体で使用回数を管理する。
- **英数字と日本語の境界スペースはルールを1つに統一**（このサイトは「入れない」で統一）。
- **金額・単位などローカライズ判断はユーザーに確認**：ドル/円建ては商流依存。勝手に換算せず確認する（今回はドル建て維持の判断）。
- **`word-break: keep-all` 下では `<wbr>`/ZWSP の改行機会が Chromium で抑制される**：仕様上は効くはずだが実ブラウザで折り返さない。確実に改行位置を制御したい見出し等では、レスポンシブに効かせた強制改行 `<br class="sm:hidden">`（モバイルのみ表示、`sm`以上は`display:none`）を使う方が堅実。
- **コピーの文字数はレイアウトに影響する**：見出しを1文字伸ばすだけで狭幅で見切れることがある。コピー変更後はモバイル幅で必ず実描画確認する。
- **多言語サイトは言語ごとに折り返し要件が異なる**：日本語向けの強制改行を英語ページにそのまま入れると語が不自然に分かれる。ページが別ファイルなら言語別に最適化する。

## 英語コピー/提案
- **`<title>` は SEO と直結するため、変更提案は慎重に**：ブランドの主張（キャッチコピー）をそのまま残したいという判断もある。提案するなら現状維持案も並べる。
- **ナビなどのUIラベルは、実在する大手IT企業（Anthropic, AWS, Google, Stripe 等）の実例を調べてから提案する**：感覚で「短くする」だけの案は根拠が弱い。
- **コピーが長くなったら全ブレークポイントで実測する**：`whitespace-nowrap` が付いた見出しは、文言が伸びると中間幅（640〜1279px）で画面外にはみ出す。
- **ナビの問い合わせ導線をボタン化するのは、ユーザーの好みで戻されることがある**：大手の流儀に合わせた変更でも、見た目の変化が大きいものは単独で確認してもらう（ラベル・並び替えと分けて提案する）。
- **Tailwind の `container` は画面幅に応じて段階的に広がる（lg 1024 / xl 1280 / 2xl 1536）**：`100vw` 基準で文字サイズを計算すると、コンテナが固定の区間（例: 1024〜1279px）ではみ出す。コンテナの段階に合わせてブレークポイントで指定する。

## 日本語の改行（追記）
- **文節改行（BudouX + `keep-all`）は見出しとリード文だけに使う**：本文や幅の狭いカードにまで使うと、行が途中で終わって右端がガタガタになる。本文は通常の組み方（禁則あり）の方が読みやすい。
- **箇条書きは1行に収まる長さで書く**：長いと文節の中で無理に折り返され、「ワークショッ / プ」のような切れ方になる。
- **翻訳調の目印を避ける**：ダッシュ（——）の多用、「確かな」「力強く」「お客様の〜」の繰り返しは、英語からの直訳やAIの文章に見える原因になる。
- **自作CSSで Tailwind のユーティリティを上書きするときは優先度に注意**：同じ優先度だと、後から読み込まれる Tailwind CDN のスタイルが勝つ（`.hero-copy` が `lg:w-3/5` に負けた）。

## 画像生成
- **社内ゲートウェイは画像編集 API（`/images/edits`）を許可していないことがある**：先に1枚で試す。使えない場合は、残したい構図・人物・服装・画面の内容を文章で細かく指定して新規生成する。
- **AI生成の集合写真は「顔が似る」「全員同じ笑い方」「服装がそろう」が不自然さの原因になる**：年齢・髪型・眼鏡・表情・服装を一人ずつ指定する。
- **画面やモニターは向きと中身に違和感が出やすい**：「画面は人物の方を向く」「ゲージの針はそれぞれ違う値」「ピンは目的地だけ」など、現実の画面の作りまで指定する。
- **`sips -Z` は縮小だけでなく拡大もする**：元より大きい値を指定すると画像が引き伸ばされる。
